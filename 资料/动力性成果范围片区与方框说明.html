1. 您看到的现象是什么

运行动力性分析时，往往有这样的观感：

  • 交通、环境、设施、政策四个准则层的中间结果，在地图上大致还贴着中心城区 / 片区的不规则轮廓，范围外多为空白（NoData）或没有有效分值；
  • 合成最终的动力性得分栅格 mot_score 后，地图上却出现一块完整的矩形（方框），方框四个角、凹进去的区域也被填上了颜色；
  • 这些方框内、但实际建成区 / 片区多边形之外的像元，分值往往接近 0 或全场最低，图上却和有效区一样被渲染成一片色块。

四准则中间成果（示意）

彩色 ≈ 有分析意义的片区内像元
灰底 ≈ 无数据 / 未参与

mot_score 现状（示意）

整幅矩形都有值（多为 0）
片区外也被「铺满最低分」

您提出的诉求可以概括为：最终动力性成果也应只表达中心城区（StudyArea）范围内，方框外不应再显示无意义的最低值。

2. 「这句话」在说什么

表述含义
四个度的分析结果范围都是片区以内 缓冲、服务区、面要素赋分等主要作用于建成区及其周边；在专题图上有效信息集中在 StudyArea 多边形附近，范围外多为 NoData 或无效像元。
叠加动力性得分以后变成范围所在的方框 程序用中心城区图层的外包矩形（Extent）作为栅格分析范围，而不是用多边形裁剪（Mask）；合成 mot_score 后，整块矩形每个像元都有数值。
范围外也没有数值都是最低值，表达出来没有意义 标准化与加权时把 NoData 当成了 0 分；矩形内、片区外的像元因此被算成「极低动力」，在图上仍占面积，既不能代表真实评价，也容易误导读图。
能否还是用中心城区的范围 希望最终 mot_score（及下游 pot_score）在空间表达上与中心城区边界一致：片区外为 NoData 或透明，不参与色带与面积统计。
一句话：不是算错了「片区内的分」，而是显示范围从「不规则城区」变成了「城区外包矩形」，且矩形外无效区被填成了最低分，图上看起来没有表达价值。

3. 技术原因（当前程序怎么做）

3.1 Extent（外包矩形）≠ Mask（按面裁剪）

动力性引擎在分析前会读取 StudyArea（中心城区），并调用：

_gp.SetExtent(extentPath); // extentPath = StudyArea 要素类路径

ArcGIS 环境里的 extent 使用的是图层的最小外接矩形，不是多边形本身。所有栅格（缓冲、叠置、加权）都在这个矩形网格上生成，矩形内每个格点都会参与运算。

3.2 NoData 在合成时被当成 0 分

准则层标准化到 0–100 时，当前公式为：

Con(IsNull("准则栅格"), 0, "准则栅格") / 理论满分 × 100

四准则加权求和时，同样对 NoData 填 0 再相加。于是：

  • 片区内、有设施/政策等的像元 → 正常分值；
  • 片区外、原本无数据的像元 → 被强制写成 0，再进入 mot_score。

对应代码：BufferScoreRasterBuilder.NormalizeTo100、WeightedSum；MotivationAnalysisEngine.Run 末尾生成 mot_score。

3.3 为什么单看四准则「像片区」，合成后「像方框」

阶段栅格范围片区外像元地图观感
单准则（如环境缓冲） 矩形 Extent 多为 NoData ArcMap 常把 NoData 显示为透明 → 只看到片区附近有色
mot_score 合成后 同一矩形 NoData 已变 0 0 会参与分级设色 → 整幅矩形都有颜色，呈方框状
因此：不是四准则算出了方框外的真实动力，而是合成步骤把「无数据」统一成了「最低分」，再在整个外包矩形上出图。

4. 从四准则到 mot_score 的数据链

StudyArea 面要素
　↓ SetExtent（外包矩形，非裁剪）
交通 / 环境 / 设施 / 政策 准则栅格（矩形内；片区外多 NoData）
　↓ NormalizeTo100（NoData → 0）
ntraf / nenv / nfac / npol（矩形内全有 0–100 数值）
　↓ WeightedSum（再次 Con NoData→0）
mot_score（矩形内每个像元都有分，片区外≈0）
　↓ 【可选】成果掩膜（StudyArea，Extract by Mask）← 全局设置默认开启
mot_score（仅中心城区内有值，片区外 NoData）
　↓ 下游叠置可行度
pot_score / pot_level（全局设置开启时同步掩膜）

下游「综合潜力」若直接对 mot_score 做加权，会继承同样的矩形范围，除非在叠置或导出前增加按 StudyArea 的掩膜。

5. 为什么方框外「没意义」却要显示

  • 统计误导：直方图、各级面积会把大量 0 分像元算进去，拉低均值、挤占「偏低」档面积；
  • 图面误导：读者以为整幅矩形都是评价对象，而实际只有中心城区多边形内才有业务含义；
  • 与规划边界不一致：汇报材料通常只展示「建成区 / 中心城区」，方框四角与凹口处的色块容易被质疑；
  • 与四准则图层不一致：同一项目里准则图「像城区」，总图「像方框」，口径不统一。
片区外像元的 0 分不代表「该区动力为零」，只代表「未纳入分析 / 无数据被当零」 — 用色块表达出来确实没有意义。

6. 与「中心城区范围」的区别

概念几何含义当前 mot_score期望表达
StudyArea Extent 多边形的最小外接矩形 栅格行列覆盖整个矩形 仅作分析环境，不宜作为成果边界
StudyArea 多边形 中心城区真实边界 未用于最终裁剪 成果应与此一致
NoData 未评价区域 合成前存在，合成后变 0 片区外保持 NoData，不出图
0 分 评价了且极低 与 NoData 混淆 仅片区内可出现 0 分

7. 改进方向（方案对比）

以下为后续可落地的技术选项，本文档不修改程序；确认后可择一或组合实施。

方案做法优点注意
A 成果掩膜（推荐） mot_score 生成后，对 StudyArea 做 Extract by Mask，输出 mot_score（或 mot_score_m）；片区外 NoData 改动小；与「外部交通仅裁切」思路一致；图面立刻恢复城区形 下游叠置、宗地关联须约定读掩膜后栅格或同步掩膜 pot_score
B 合成时掩膜 WeightedSum 表达式内对 StudyArea 外写 NoData，而非 0 从源头避免「假 0」进入加权 表达式较复杂；四准则标准化也需统一策略
C 仅显示层掩膜 不改 GDB，地图加载时用 StudyArea 多边形作 Clip / 定义显示范围 零算法改动 导出 TIFF、面积统计仍会带方框；不同人出图口径易不一致
D 全流程掩膜 四准则标准化后、加权前均按 StudyArea 裁切；pot_score 同样处理 中间成果与最终成果范围一致 工作量最大；需回归测试全链路
推荐：方案 A（各模块最终成果合成后掩膜），通过全局设置中一项开关 MaskResultToStudyArea（默认开启）统一控制动力性 mot_score、可行度 fea_score、叠置 pot_score / pot_level。详见 分析成果掩膜 — 全局设置方案。

8. 全局设置：成果掩膜（默认开启）

原设计为在动力性分析窗体单独增加 Checkbox；经确认改为在全局设置（GlobalSettingsForm）统一配置，动力性 / 可行度 / 叠置三模块共用，避免口径不一致。

完整方案见：分析成果掩膜 — 全局设置方案（配置项、界面、引擎落地、验收清单）。

8.1 配置项摘要

项目说明
属性名 GlobalAppSettings.MaskResultToStudyArea
界面位置 数据管理 → 全局设置 →「分析成果按中心城区掩膜」
默认值 true（默认勾选）
持久化 %LocalAppData%\UrbanRenewal\Config\app_settings.xml
控制成果 mot_score、fea_score、pot_score、pot_level

8.2 与动力性的关系

动力性分析窗体不再增加 chkMaskResultToStudyArea；引擎在写出 mot_score 前读取全局设置，若开启则对 StudyArea 执行 Extract by Mask。

外部交通「按中心城区裁切」仍保留在动力性窗体，属于输入数据处理，与成果掩膜无关。

8.3 处理流程（全局开启时）

WeightedSum → mot_score（矩形）
　↓ if MaskResultToStudyArea → Extract by Mask（StudyArea 面）
mot_score（掩膜后正式成果，片区外 NoData）
日志：「已按全局设置掩膜动力性成果」

9. 出图与汇报时的临时做法（改程序前）

在程序尚未按城区掩膜前，若需避免方框误导，可临时：

  1. 在 ArcMap 中将 mot_score 图层的 NoData 设为无色（若当前为 0 则需先识别 0 是否为假 NoData）；
  2. 用 StudyArea 面做数据框裁剪或按形状裁剪导出专题图；
  3. 面积统计、分级占比仅在 StudyArea 内用按掩膜提取或分区统计重算，勿直接对整幅矩形计数。
临时做法无法从根上区分「真 0 分」与「原 NoData 变 0」；长期仍建议程序内方案 A。

10. 改完后如何验收

  1. 全局设置默认勾选：打开「全局设置」，「分析成果按中心城区掩膜」应为勾选状态；
  2. 勾选并运行动力性：加载 mot_score，片区外为 NoData / 透明，轮廓与 StudyArea 一致；
  3. 全局取消勾选并重跑：行为与改前一致，仍为矩形方框（用于对比回归）；
  4. 片区内像元值与未掩膜前同位置对比应一致；
  5. 可行度 fea_score、叠置 pot_score / pot_level 在全局开启时均为城区形；
  6. 直方图、五级面积表：全局开启掩膜后不应含外包矩形角落的 0 分像元；
  7. 日志含「已按全局设置掩膜成果」或各模块等价说明。

确认 全局设置方案 后，可下达开发指令（GlobalAppSettings + 全局设置窗体 + 各分析引擎）。
