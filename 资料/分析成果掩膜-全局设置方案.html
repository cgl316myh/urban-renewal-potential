1. 背景与目标

动力性、可行度、叠置评价在 GP 环境中使用 StudyArea 的外包矩形 Extent 作为分析范围；标准化与加权步骤将 NoData 统一为 0，导致最终成果栅格（mot_score、fea_score、pot_score、pot_level）铺满矩形，片区外出现无意义的低分色块。

改进采用方案 A：成果掩膜 — 各模块在写出最终成果栅格前，对 StudyArea 面要素执行 Extract by Mask，片区外保持 NoData。

控制方式：不在各分析窗体重复放 Checkbox，而在全局设置（GlobalSettingsForm）中配置一项开关，持久化到 app_settings.xml，动力性 / 可行度 / 叠置引擎运行时统一读取。

现象与根因详见 动力性成果范围片区与方框说明。

2. 为何做成全局设置

对比项各窗体单独 Checkbox全局设置（本方案）
口径一致性 用户可能在动力性勾选、叠置未勾选，综合图仍为方框 一次配置，全链路一致
与现有模式 与像元大小、叠置权重等「全局共用」项割裂 与 CellSize、MotivationWeight 等同属 GlobalAppSettings
界面复杂度 三个窗体各加一个控件，易遗漏 分析窗体保持简洁，仅「数据管理 → 全局设置」一处
持久化 需写入各 Job 或重复读窗体状态 写入用户目录 %LocalAppData%\UrbanRenewal\Config\app_settings.xml
说明：动力性窗体「外部交通 → 按中心城区裁切」(ClipExternalTrafficToStudyArea) 是输入数据裁切，与本项最终成果掩膜不同，仍保留在动力性窗体，不受全局开关替代。

3. 作用范围与掩膜对象

3.1 受全局开关控制的模块

模块引擎掩膜时机正式成果数据集
动力性分析 MotivationAnalysisEngine WeightedSum 得到矩形 mot_score 之后 mot_score
可行度分析 FeasibilityAnalysisEngine 写出 fea_score 之前（合成/标准化完成后） fea_score
叠置评价 OverlayAnalysisEngine pot_score、pot_level 写出之前 pot_score、pot_level

3.2 不在此开关范围内的内容

  • 中间准则栅格（交通/环境/设施/政策、坡度/人口等中间层）：仍可在矩形 Extent 上计算，不必逐个掩膜；
  • 宗地关联（ParcelLinkEngine）：读取已掩膜的 pot_score，无需单独开关；
  • 成果导出：导出 GDB 中已有栅格，随上游成果范围；
  • 验证校核：统计模块，非连续面状成果。

3.3 可选保留的调试数据集

数据集含义默认地图加载
mot_score_raw / pot_raw 等掩膜前的矩形版，备查与回归对比否
mot_score、fea_score、pot_score、pot_level掩膜后的正式成果是

4. 全局配置项

4.1 模型（GlobalAppSettings）

/// 分析最终成果是否按 StudyArea 掩膜；默认 true。动力性/可行度/叠置共用。
public bool MaskResultToStudyArea { get; set; } // 构造函数中默认 true

4.2 持久化（app_settings.xml 片段）

<MaskResultToStudyArea>true</MaskResultToStudyArea>

旧版配置文件无此节点时，反序列化后由构造函数默认值为 true；与 CellSize 缺省 30 米策略一致。

4.3 开关行为

值行为适用场景
true（默认） 各模块最终成果经 Extract by Mask，片区外 NoData 正常生产、出图、汇报
false 保持现状矩形成果，与改前算法一致 与历史结果对比、调试中间矩形 Extent

5. 界面：全局设置窗体

在 GlobalSettingsForm（数据管理 → 全局设置）中，于「像元大小」行下方增加复选框，与现有分析参数分组相邻。

5.1 控件示意

全局设置 · 分析参数区域（示意）

像元大小(米)：

默认勾选。取消后各分析模块输出矩形范围成果（与当前版本一致）。保存后立即写入 app_settings.xml。

5.2 控件属性（Designer）

项目说明
控件名chkMaskResultToStudyArea
显示文本分析成果按中心城区掩膜（动力性/可行度/叠置）
默认值Checked = true
位置nudCellSize 下方；lblHint 文案扩展说明本项
窗体高度适当增加（约 +28px），按钮区下移

5.3 保存逻辑（btnSave_Click）

_context.MaskResultToStudyArea = chkMaskResultToStudyArea.Checked;
_context.SaveGlobalSettings();

保存成功提示中增加一行，例如：成果掩膜=是/否。

5.4 lblHint 建议文案

像元大小供动力性/可行度/叠置等潜力分析共用。勾选「分析成果按中心城区掩膜」时，mot_score、fea_score、pot_score、pot_level 写出前将按 StudyArea 裁切；需 GDB 中存在分析范围图层。

6. 运行时读取（IAppContext）

与 CellSize 相同模式，在 IAppContext / AppContextImpl 暴露属性，各插件通过注入的 IAppContext 或 GlobalAppSettingsStore.Load() 读取。

// IAppContext
bool MaskResultToStudyArea { get; set; }

// AppContextImpl — 读写 _settings.MaskResultToStudyArea

分析 Job 对象不必再增加 MaskMotivationResultToStudyArea 等字段；引擎在 Run 入口读取全局设置即可。若需日志追溯，可在运行日志中记录当前全局值。

7. 各分析引擎落地

7.1 动力性（MotivationAnalysisEngine）

WeightedSum → mot_score（矩形，或先写 mot_score_raw）
if (GlobalAppSettings.MaskResultToStudyArea && studyLayer != null)
　Extract by Mask(studyLayer) → 覆盖 mot_score
else if (开启但无 StudyArea) → 记录警告并中止或跳过掩膜（见 §9）

7.2 可行度（FeasibilityAnalysisEngine）

合成 fea_score（矩形）
if (MaskResultToStudyArea) → Extract by Mask → fea_score

可行度同样使用 SetExtent(StudyArea) 与 NormalizeRangeTo100（NoData→0），存在与动力性相同的方框问题，须同步掩膜。

7.3 叠置（OverlayAnalysisEngine）

WeightedOverlay(mot, fea) → pot_raw → pot_score
ClassifyLevels → pot_level
if (MaskResultToStudyArea) → 对 pot_score、pot_level 分别 Extract by Mask
即使上游 mot_score、fea_score 已掩膜，PotentialOverlayBuilder.WeightedOverlay 仍将 NoData 当 0 参与运算，矩形 Extent 内可能重新出现低分像元；叠置最终写出前仍须掩膜。

等级面积统计（ComputeLevelAreas）在掩膜后的 pot_level 上执行，可避免矩形角落假像元计入占比。

8. 共享 GIS 辅助

在 UrbanRenewal.GIS 增加统一方法（可置于 ExternalRasterHelper 或新建 ResultMaskHelper），避免三处重复 GP 代码：

public static string MaskRasterToStudyArea(
　　GeoprocessorHelper gp,
　　string sourceRasterPath,
　　string studyAreaFeaturePath,
　　string outputRasterPath)
// ExtractByMask；失败抛异常或返回 null，由引擎写日志

与外部交通裁切（PrepareExternalTrafficRaster 内 Extract by Mask）使用同一 GP 工具，仅输入输出语义不同：本方法针对分析成果栅格。

9. 全链路数据流

全局设置
MaskResultToStudyArea → 动力性
mot_score → 可行度
fea_score → 叠置
pot_score / pot_level → 宗地关联 / 导出
StudyArea 面要素
　↓ SetExtent（矩形，GP 环境不变）
中间准则 / 因子栅格（矩形内计算）
　↓ 各模块合成最终分
mot_score_raw / fea_score_raw / pot_raw（矩形，可选保留）
　↓ if MaskResultToStudyArea → Extract by Mask
mot_score / fea_score / pot_score / pot_level（城区形，片区外 NoData）
　↓ 地图默认加载、导出、宗地 zonal 统计

10. 异常与前置条件

情况建议处理
全局勾选掩膜，但 GDB 无 StudyArea 运行前检测；中止并提示「已启用成果掩膜，但未找到分析范围图层 StudyArea」
全局未勾选掩膜 不执行 Extract by Mask，行为与现版一致；不强制要求 StudyArea
StudyArea 几何为空或无效 GP 失败时写日志，分析结果 Success=false
用户修改全局设置后未重跑分析 GDB 中仍是旧成果；属预期，提示用户重新运行相关模块

StudyArea 解析规则与各引擎现有一致：角色键 StudyArea，别名「中心城区」「分析范围」「建成区」等。

11. 实施分期

期次内容说明
一期 GlobalAppSettings + 全局设置窗体 + IAppContext + ResultMaskHelper + 动力性 mot_score 最小可用，解决动力性方框
二期 可行度 fea_score + 叠置 pot_score / pot_level 全链路口径一致
可选 保留 *_raw 矩形数据集、日志增强 便于回归对比
开发指令建议：确认本 HTML 后，可按一期 → 二期顺序下达实现；各期独立可测，一期上线后动力性图面即可恢复城区形。

12. 验收清单

  1. 打开「全局设置」，chkMaskResultToStudyArea 默认勾选；保存后 app_settings.xml 含 <MaskResultToStudyArea>true</MaskResultToStudyArea>；
  2. 勾选状态下运行动力性：加载 mot_score，片区外 NoData/透明，轮廓与 StudyArea 一致；
  3. 取消勾选并重跑：仍为矩形方框（回归对比）；
  4. 片区内像元值与掩膜前同位置一致；
  5. 可行度 fea_score、叠置 pot_score / pot_level 在勾选时均为城区形；
  6. 叠置等级面积表不含矩形角落假像元；
  7. 勾选掩膜但无 StudyArea 时，分析中止并提示；
  8. 重启程序后全局设置仍保留；动力性/可行度/叠置窗体无重复 Checkbox；
  9. 日志含「已按全局设置掩膜成果」或各模块等价说明。
