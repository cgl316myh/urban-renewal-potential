1. 需求与目标

1.1 业务诉求

部分城市已在 ArcGIS / 其他工具中完成中心城区交通便捷度分析（路网服务区、综合打分等），希望将该结果栅格直接作为动力性「交通便捷度」准则层，与内置计算的环境 / 设施 / 政策准则一起标准化、加权，输出 mot_score，无需重复跑地铁缓冲、路网求解等步骤。

1.2 设计目标

  • 提供稳定、可配置的接入接口（路径 + 分值语义 + 可选范围）
  • 指定外部栅格时跳过 BuildTraffic() 内置流程
  • 软件内仅做裁切（按中心城区 StudyArea）；不做重投影、不做重采样
  • 运行前校验外部栅格坐标系、像元大小是否与系统分析环境一致；不一致则弹窗警告并中止，提示用户在外部 GIS 中自行处理
  • 与现有四准则加权、mot_score、下游叠置 / 宗地关联完全兼容
  • 未指定外部栅格时，行为与现版零变化
硬性约束：本功能不在程序内调用 Project Raster、Resample、Define Projection 等工具。空间参考与像元大小必须由用户在 ArcGIS 等外部环境中预先处理好，与本系统全局设置（CellSize、分析用坐标系）一致后再接入。
结论：可行。叠置模块已有「栅格名或完整路径」解析模式（OverlayJob.MotivationRasterName），交通准则层可复用同一思路，在动力性引擎入口增加「外部交通栅格」分支即可。

2. 现状与缺口

2.1 当前动力性交通分支

地铁多环缓冲 + 路网服务区 1–5 + CBD / 交通设施 → MAX 合并 → traffic 原始分 0–5 → ÷5×100 → ntraf → 四准则加权 → mot_score

入口：MotivationAnalysisEngine.Run → BuildTraffic；理论满分 MotivationScoreScale.TrafficMax = 5。

2.2 缺口

能力现状缺口
外部栅格输入 无 MotivationJob 无交通栅格路径字段
跳过内置交通 始终执行 BuildTraffic 需分支：有外部栅格则跳过
空间处理 内置流程自动 ConfigureAnalysis 外部栅格仅 Clip；投影/像元须预检，不匹配则警告中止
分值语义 假定原始分 0–5 外部可能为 0–100 或 1–5，需声明
UI / 配置持久化 动力性窗体仅权重 需浏览路径、模式选择、写入 CityProfile

3. 接口设计（核心）

3.1 作业参数扩展 — MotivationJob

/// 外部交通栅格接入（可选）。指定后跳过 BuildTraffic。
public string ExternalTrafficRasterPath { get; set; }

/// 外部栅格分值语义：Raw（原始分，默认）| Normalized（已 0–100）。
public string ExternalTrafficScoreMode { get; set; } // "Raw" | "Normalized"

/// Raw 模式下的理论满分，默认 5（与 TrafficMax 一致）。
public double ExternalTrafficRawMax { get; set; } // default 5.0

/// 是否按中心城区 StudyArea 裁剪外部栅格；默认 true。
public bool ClipExternalTrafficToStudyArea { get; set; } // default true

/// 输出库内落地名，默认 traf_ext。
public string ExternalTrafficOutputName { get; set; } // "traf_ext"

3.2 城市配置扩展 — CityProfile（持久化）

字段类型说明
ExternalTrafficRasterPath string 默认外部交通栅格路径（GDB 内数据集名、完整路径或 TIFF 均可）
ExternalTrafficScoreMode string Raw / Normalized，默认 Raw
UseExternalTraffic bool 是否启用外部交通栅格；false 时走内置 BuildTraffic

写入 Config/Cities/*.xml，由「系统配置」或「动力性分析」窗体保存。

3.3 服务接口 — IMotivationTrafficSource（可选，便于插件化）

namespace UrbanRenewal.Contracts
{
  /// <summary>动力性交通准则层数据源；内置计算与外部栅格二选一。</summary>
  public interface IMotivationTrafficSource
  {
    /// <summary>是否使用此外部源（由 Job / Profile 决定）。</summary>
    bool IsExternal { get; }

    /// <summary>
    /// 解析并准备交通准则原始栅格（已通过空间校验，仅裁切）。
    /// 返回输出 GDB 内栅格完整路径；失败返回 null 并写入 messages。
    /// </summary>
    string PrepareTrafficRaster(
      GeoprocessorHelper gp,
      MotivationJob job,
      ISpatialReference targetSr,
      string studyAreaPath,
      IList<string> messages);

    /// <summary>标准化到 0–100 时使用的理论满分；Normalized 模式返回 100。
    double GetScoreMaxForNormalization();
   }
}

第一档可不单独建接口类，仅在 MotivationAnalysisEngine 内实现 ResolveExternalTraffic() 静态方法；第二档再抽接口供第三方插件实现自定义交通源。

4. 处理流程

4.1 总流程（外部栅格启用时）

读取 Job / Profile
UseExternalTraffic=true → 解析路径
ExternalTrafficRasterPath → 空间一致性校验
投影 + 像元大小 → 不匹配？
弹窗警告 · 中止 → Extract by Mask
（按 StudyArea 裁切） → 写入输出 GDB
traf_ext → 标准化 ntraf
（Raw÷5×100 或直通） → 与环境/设施/政策
WeightedSum → mot_score
程序内唯一的空间运算：按中心城区（StudyArea）对已通过校验的外部栅格做裁切（Extract by Mask）。不执行重投影、重采样、对齐 Extent。

4.2 引擎内伪代码

// MotivationAnalysisEngine.Run 内，原 BuildTraffic 处改为： string traffic = null; double trafficScoreMax = MotivationScoreScale.TrafficMax; if (ShouldUseExternalTraffic(job)) { Report(..., "校验外部交通栅格空间属性...", 18); ExternalRasterCheckResult check = ValidateExternalTrafficRaster( externalPath, _targetSr, job.CellSize); if (!check.IsCompatible) { // UI 层（MotivationRunForm）或引擎回调弹出 MessageBox，中止本次分析 ShowSpatialMismatchWarning(check); // 见 §4.5 return result; // Success = false } Report(..., "使用外部交通栅格（仅裁切）...", 20); traffic = ResolveExternalTraffic(_gp, job, _extentPath, result); if (job.ExternalTrafficScoreMode == "Normalized") trafficScoreMax = 100.0; } else { Report(..., "交通便捷度分析（内置）...", 20); traffic = BuildTraffic(job, names, result); } // 后续 criterionRasters / scoreMaxes 使用 trafficScoreMax

4.3 新增 GIS 辅助方法

方法职责是否执行 GP 变换
ExternalRasterHelper.ValidateCompatibility 读取外部栅格 SR、CellSize X/Y，与系统目标 SR、job.CellSize 比对 否（只读元数据）
ExternalRasterHelper.ClipRasterByStudyArea Extract by Mask（StudyArea 面）；范围外 NoData 是（仅裁切）
ExternalRasterHelper.CopyToOutputGdb 将裁切结果写入输出 GDB traf_ext 是（Copy Raster）
ExternalRasterHelper.ValidateRasterValueRange 可选：检查 min/max，Raw 模式警告超出 0–5 否
AlignExternalRaster / ProjectRaster / Resample 明确不做

4.4 输出产物

数据集含义
traf_ext裁切后的外部交通原始栅格（写入输出 GDB）
ntraf 或 ntrafn交通准则标准化 0–100（与现命名一致）
mot_score四准则加权结果（不变）
MotivationResult.CriterionRasters["交通便捷度"]指向 traf_ext，日志标注「外部接入」

5. 空间一致性校验（不重投影 / 重采样）

5.1 原则

外部交通栅格接入时，程序只读取栅格的空间参考与像元大小，与当前动力性分析环境比对。不在本软件内做任何坐标转换或重采样；不一致时弹窗警告并中止本次分析，由用户到 ArcGIS 等外部工具中处理完毕后再重新运行。

5.2 系统基准（比对目标）

基准项来源说明
目标坐标系 MotivationAnalysisEngine.Run 中 _targetSr 优先 StudyArea 图层 SR；否则回退 CBD 等（与现动力性分析一致）
目标像元大小 job.CellSize / 全局 GlobalAppSettings.CellSize 默认 30（米）；X、Y 方向均须一致

5.3 校验规则

检查项判定方式容差
坐标系 ISpatialReferenceFactory.CreateESRISpatialReferenceFromPRJFile 或 ISpatialReference.Name / FactoryCode 比对；可用 SpatialReferenceAudit 同类逻辑 名称与 FactoryCode 均一致；或 PRJ 字符串等价（投影参数一致）
像元大小 X 读取 IRasterProps.MeanCellSize() 或 Geoprocessing Get Raster Properties |外部 − 系统| ≤ 0.01 m（或相对误差 < 0.1%）
像元大小 Y 同上 同上；且 X≈Y（正方形像元，与内置分析一致）
范围覆盖（建议） 外部栅格 Extent 应包含 StudyArea 外包矩形 不满足时警告（裁切后可能缺边），可不硬中止；与投影/像元硬错误区分

5.4 校验结果类型

public sealed class ExternalRasterCheckResult
{
  public bool IsCompatible { get; set; }
  public bool SpatialReferenceMismatch { get; set; }
  public bool CellSizeMismatch { get; set; }
  public string ExpectedSpatialReference { get; set; }
  public string ActualSpatialReference { get; set; }
  public double ExpectedCellSize { get; set; }
  public double ActualCellSizeX { get; set; }
  public double ActualCellSizeY { get; set; }
  public string SummaryMessage { get; set; }
}

5.5 警告框文案（投影 / 像元不匹配时）

标题：外部交通栅格空间属性不匹配

外部交通栅格与当前分析环境不一致，无法继续。
本程序不会自动重投影或重采样，请在外部 GIS 中处理后再导入。

【坐标系】
　系统要求：{ExpectedSpatialReference}
　当前栅格：{ActualSpatialReference}

【像元大小】
　系统要求：{ExpectedCellSize} m
　当前栅格：X={ActualCellSizeX} m，Y={ActualCellSizeY} m

建议操作（ArcGIS）：
　1. 投影：数据管理工具 → 投影和变换 → 投影栅格
　2. 重采样：数据管理工具 → 栅格 → 栅格处理 → 重采样
　 像元大小设为 {ExpectedCellSize}，与全局设置一致
　3. 处理完成后重新选择栅格并运行动力性分析

[确定]

图标：MessageBoxIcon.Warning；仅「确定」按钮，点击后 MotivationResult.Success = false，日志写入 SummaryMessage。

5.6 校验时机

时机行为
点击「运行」后、裁切前 后台线程执行校验；失败则 UI 线程弹窗，不进入 GP 裁切
浏览选择栅格后（可选增强） 即时轻量校验，文本框旁显示 ✓ / ✗ 状态，减少跑一半才失败
推荐：第一档在「运行」时做完整校验并弹窗；第二档增加选择路径后的即时预检（只读元数据，不裁切）。

6. 输入栅格规范

6.1 推荐格式

项目要求
空间范围 至少覆盖中心城区 StudyArea；可更大，程序仅按 StudyArea 裁切
坐标系 必须与系统分析坐标系完全一致；程序不自动投影，不一致则警告中止
像元大小 必须与全局 CellSize（默认 30 m）一致；程序不自动重采样，不一致则警告中止
分值（Raw 模式） 整数或浮点 0～5（与内置交通一致）；NoData 表示无数据
分值（Normalized 模式） 0～100，已标准化，跳过分母除法
文件格式 File GDB 栅格数据集、GeoTIFF、IMG 等 ArcGIS 可读格式

6.2 典型来源示例

  • 本系统历史某次动力性输出的 trafficmx / 交通中间栅格
  • 单独跑路网服务区后手工合并的 1–5 分栅格
  • 其他 GIS 项目导出的中心城区交通便捷度 TIFF
  • 输出 GDB 内预置数据集名 traf_import
注意：外部栅格须在外部 GIS 中预先完成投影与重采样，再导入本系统。程序只负责按 StudyArea 裁切；若投影或像元与系统不匹配，将弹窗提示并中止，不会代为转换。

6.3 外部预处理流程（用户须在 ArcGIS 等工具中完成）

在将栅格导入本系统之前，用户应完成以下步骤（本软件不执行）：

  1. 在「数据管理 → 全局设置」或动力性窗体查看系统要求的坐标系与像元大小（如 CGCS2000 3° 带 + 30 m）
  2. 若外部栅格坐标系不同 → 投影栅格（Project Raster）到系统坐标系
  3. 若像元大小不同 → 重采样（Resample）到 CellSize，建议双线性或最邻近（分值栅格可用最邻近保整数档）
  4. 确认栅格范围至少覆盖中心城区 StudyArea
  5. 在本系统勾选「使用外部交通栅格」，选择处理后的路径并运行；程序仅做裁切并参与叠加
ArcGIS 工具用途本系统是否调用
投影栅格（Project Raster）统一坐标系否 — 用户外部完成
重采样（Resample）统一像元大小否 — 用户外部完成
按掩膜提取（Extract by Mask）按 StudyArea 裁切是 — 程序内唯一空间变换

10. 风险与对策

风险对策
坐标系 / 像元不一致 运行前 ValidateCompatibility；不匹配弹窗中止，提示用户外部 Project Raster / Resample
外部分值尺度错误（如 0–100 却选 Raw） 运行前 GetRasterProperties 检查 min/max 并警告；文档明确规范
无 StudyArea 无法裁剪 提示用户；或回退为外部栅格自身 Extent
与内置交通结果不可比 日志与元数据标注 traffic_source=external；报告说明口径
路径失效 / 文件被锁 启动前校验存在性；失败则中止或询问是否改走内置交通
范围外 NoData 污染加权 NormalizeTo100 已将 NoData→0；裁剪后研究区外不参与展示

11. 分档落地计划

第一档 · 最小可用（推荐先做）

  1. MotivationJob 增加 ExternalTrafficRasterPath、ExternalTrafficScoreMode、UseExternalTraffic
  2. ExternalRasterHelper.ValidateCompatibility：投影 + 像元校验；失败弹窗中止
  3. ResolveExternalTraffic：仅 StudyArea 裁切 + 写入 traf_ext（无 Project/Resample）
  4. Run 内：启用时跳过 BuildTraffic
  5. MotivationRunForm：勾选 + 路径浏览 + 分值模式 + 校验失败 MessageBox
  6. 日志明确打印「交通准则：外部栅格（仅裁切）」及路径

第二档 · 配置持久化

  1. CityProfile XML 字段 + 系统配置窗体
  2. 栅格统计校验（min/max 预警）
  3. 输出 traffic_source.txt 元数据到输出 GDB 旁

第三档 · 扩展

  1. IMotivationTrafficSource 插件接口
  2. 支持「外部交通 + 内置地铁加分」混合模式（高级，非必需）
  3. 批量城市模板预置外部栅格路径

12. 验收建议

  1. 分支正确：勾选外部栅格后日志无「地铁缓冲」「路网服务区」字样，有「使用外部交通栅格（仅裁切）」
  2. 投影不匹配：故意使用 WGS84 栅格 → 弹窗警告，列出系统要求 vs 实际坐标系；分析中止，无 traf_ext / mot_score 更新
  3. 像元不匹配：故意使用 10 m 栅格（系统 30 m）→ 弹窗警告，列出像元 X/Y；分析中止
  4. 匹配后裁切：投影与像元均正确 → 通过校验，生成 traf_ext，范围与 StudyArea 一致
  5. 空间一致：traf_ext 与内置准则栅格 SR、像元大小一致（因未做重投影/重采样，应与输入外部栅格一致）
  6. 分值正确：Raw 模式：外部 3 分区域 → ntraf ≈ 60；Normalized 模式：外部 60 → ntraf = 60
  7. 裁剪：StudyArea 外像元为 NoData 或 0，不参与加权
  8. 回退：取消勾选后结果与改前内置交通一致
